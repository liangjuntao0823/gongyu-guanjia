## 一、b94 与最新版「总刷新」机制对比结论（禁止返工，已定论）

对 b94 基准（v1.98 返修4，commit `52c1385`）与最新版（v2.3/b110，commit `c14bdd4`）做了逐行对比：

| 对比对象 | 结论 |
|---|---|
| `MeterQueryService.swift`（直连） | `git diff 52c1385 HEAD` **零差异** |
| `MeterWebViewProvider.swift`（WebView 兜底） | **零差异** |
| `MeterStore.swift` | 仅「刷新记录保留 80→200 条」一条无关差异 |
| `MeterBoardView.swift` 刷新段 | 无逻辑差异（仅新增搜索跳转/高亮 UI） |

**核心机制两版逐行一致**：

1. **串行执行**：一台接一台刷新，单台间隔 1.5 秒（34 台约 51 秒跑完）
2. **单台重试**：`query()` 失败后等 1.5 秒重试一次，共两次机会
3. **超时 12 秒**：单台请求超时上限
4. **失败户静默跳过**：`refreshAll` 只统计 ok 台数，失败户不进列表、无任何反馈；仅当 `ok == 0` 时才抛错提示

**「每次总有几间房刷新失败」根因 = 机制特性，不是代码退化**：

- 单台只有两次机会，偶发网络抖动、单户接口瞬时异常即被放弃；
- 失败户没有任何反馈入口，用户只能看到「少数几间数据没更新」；
- 既无失败清单、也无二次轮巡，是设计缺陷而非回归 bug。

> 佐证：b104（a397f0d「电表总刷新恢复 b94 最原始串行机制」）曾把 b102/b103 的并发/倍速方案撤回，说明 b94 串行就是当前产品的稳定基线。

## 二、三项需求落地情况

### ① 取消「打开 App 后台自动全刷新」（b111）✓

- **改动**：`MeterStore.startAutoRefreshIfNeeded()` 删除原「启动即先补刷一次」的 `Task { await self.autoRefreshOnce() }`
- **效果**：打开 App 不再后台跑一遍全量刷新
- **保留**：设置页「定时自动刷新」开关开启时，仍按设定间隔（默认 30 分钟）自动刷新——这是用户认可的唯一自动路径
- 文件头注释同步更新（说明「App 下次打开不会自动补刷」）

### ② 取消「每次进入电表板块自动刷新」（b111）✓

- **改动**：`MeterBoardView` 删除 `.onAppear { autoRefreshOnEnter() }` 调用与整个 `autoRefreshOnEnter()` 方法
- **效果**：进入电表板块不再条件自动刷新（此前「无数据或全部无最近刷新记录」会触发）
- **影响**：首次使用（电表清单为空）进入板块不再自动拉绑定；点「刷新」按钮（或右上角「+」进电表管理）即可拉取绑定清单
- **保留**：顶部手动刷新按钮、列表下拉刷新均不受影响

### ③ 总刷新跑完自动重刷失败户＋仍失败弹窗（b111）✓

**改动链路（3 个文件 + 协议）**：

| 文件 | 改动 |
|---|---|
| `MeterModels.swift` | 新增 `MeterRefreshOutcome { okCount, failedUIDs }`；协议 `refreshAll` 返回 `Int` → `MeterRefreshOutcome` |
| `MeterQueryService.swift`（直连） | `refreshAll` 收集失败户：`catch` 分支 `failed.append(ledger.uid)`，返回 outcome |
| `MeterWebViewProvider.swift`（WebView） | `refreshAll` 收集失败户：`item.ok == false` 时 `failed.append(item.uid)`，返回 outcome |
| `MeterStore.swift` | `refreshNow` 适配 `outcome.okCount`（0 仍返回 0，语义不变） |
| `MeterBoardView.swift` | `refreshAll()` 二段式：第一遍 `provider.refreshAll` → 失败户非空时逐个 `query()` 串行重刷（台间 1.5 秒限速）→ 仍失败者装进 `stillFailed` → 弹窗「刷新未完成」列出房号提示手动刷新 |

**行为细节**：

- 重刷进度合并显示：`正在刷新 x/y：重刷失败户 j/n 房号`，进度条第一遍满后继续走第二段，全程单调增长到 100%
- 弹窗内容：`以下房间自动重刷后仍刷新失败，请手动刷新：房号A、房号B…`（房号为空时用户号 uid）
- 全失败（ok==0）时 provider 抛错 → 直接提示「刷新失败」，不触发重刷（此时是会话/链接级问题，重刷无意义）
- AI 抄表 / 定时刷新路径（`MeterStore.refreshNow`）按原语义静默执行，不受本轮改造影响
